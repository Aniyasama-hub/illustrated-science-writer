# 在不同智能体中运行与微调

## 统一入口

读取根目录SKILL.md，再读取references/writing.md、editorial.md、illustration.md。涉及资料核实时按写作适配查上游研究方法；涉及图型时按图文适配查上游样式。不要把上游宿主特有的命令直接当作当前环境存在的函数。

`agents/openai.yaml` 是一个宿主的界面元数据，其他智能体可以忽略。没有必要给每个宿主复制一份中控。把工具名称的差异留在宿主配置或本次运行说明中。

## 工具如何对应

| 需求 | 目标宿主的能力 | 缺少能力时 |
| --- | --- | --- |
| 文献核实 | 检索及打开原始网页、论文或用户提供全文 | 记录来源尚未打开，不用搜索摘要冒充全文证据 |
| 概念插画 | 宿主已有生图能力 | 交付提示词并记录未成图；不能称作完成配图 |
| 数值与精确数据图 | Python/R等计算工具 | 不编造计算结果；记录未复算项 |
| 简单流程图 | SVG/HTML或宿主绘图工具 | 优先可编辑几何图，不需要额外图片服务 |
| 资产检查 | 实际打开图片，检查文字、箭头、数据 | 没有看到成图时reviewed不能填true |
| 机械校验 | Python 3.9+标准库 | 可人工核查清单，但不能伪造脚本PASS记录 |

宿主自带工具可直接使用。不支持原宿主的imagegen技能时，使用目标宿主可用的原生图像工具及其规范。不在本技能内安装第三方生图SDK，也不默认调用新的付费API。

## 微调哪些文件

- 修改五节默认结构、字数范围和默认图数：`references/contract.json`。用户本次要求仍优先。
- 修改语气、术语解释和删改原则：`references/editorial.md`。
- 修改画风、配色和图型路由：`references/illustration.md`。
- 修改整体阶段和交付内容：根目录`SKILL.md`。
- 上游`upstream/`保持快照原样；要吸收新版本，应同时更新提交号、许可说明和文件哈希。

修改前记录仓库提交号；每个实验保存一份独立输出目录和运行记录，避免覆盖基线示例。先从明确的一条规则修改，观察结果后再决定是否保留。

## 公平比较生成效果

1. 所有智能体使用同一仓库版本和`benchmarks/request-wgcna.md`，各自独立生成，不读取`examples/`成稿。
2. 选择一种资料条件：开放检索模式允许各自检索，记录访问时间；固定资料模式仅提供基线sources.json中的同一组来源全文或快照。只给URL不等于提供相同全文。
3. 记录模型名称、可用工具、用时、重试、花费（可取得时）及人工修改。不能将“有生图工具”和“没有生图工具”的差异完全归因于模型文风。
4. 先验证严格章节、篇幅、实际成图数量和案例可追溯性，再盲评清晰度、推理准确性、读图价值及风格一致性。采用`benchmarks/run-record.template.json`记录，分数与评语由真实审阅者填写。
5. 输出目录中的sources/cases/images/review清单沿用本技能约定，运行机械检查器。通过结构检查之后仍逐张看图、核对案例定义和数字。

本仓库现有两个示例只证明已生成并检查过这些文章，不代表已实测所有宿主或所有题材。
